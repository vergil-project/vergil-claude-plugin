- **emit required docs / docs check via reusable ci-docs.yml (#679)**

Replace the inline job with the fleet-standard reusable ci-docs.yml@v2.1 (as every peer repo uses), so the plugin emits docs / docs and PRs can merge.

- **identify the retrospective task by label, not title (#680)**
The retrospective preflight matched the retrospective bookend by its title convention (Retrospective: <slug>). Now that vrg-issue-create --kind retrospective stamps a retrospective label (tooling 2.1.167), prefer that label for identification — mechanical matching is more robust than string-matching a title — keeping the title convention as a fallback for epics created before the label existed.

- **clarify PR batching is per-repository (#681)**
epic-implement step 4 read as a single consolidated cross-repo batch, but vrg-submit-pr takes a branch list within one repo. Clarify that the unit of submission is a repo's ready set: submit a repo's ready branches as soon as all its currently-ready tasks reach report-ready, independently of slower repos. Safe because concurrently-runnable tasks are non-interdependent by construction, so interdependent tasks are never in the same batch.
