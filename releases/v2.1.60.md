
# Release 2.1.60 (2026-11-07)

## Bug fixes

- **undo a bad rebase with commands vrg-git allows (#943)**
vrg-git denies reset, so the documented 'vrg-git reset --hard ORIG_HEAD' undo was refused exactly when needed. Use 'vrg-git rebase --abort' for a rebase in progress, and the reflog plus 'vrg-git switch -C' for a completed one; otherwise stop and ask the human. Ref #825

- **use GitHub's double-hyphen anchor for the execution-doctrine link (#946)**
GitHub drops the em dash in '## Execution doctrine — Front-Loaded Judgment, Trusted Execution' and keeps both surrounding hyphens, so the blob-URL anchor is #execution-doctrine--front-loaded-judgment-trusted-execution. The single-hyphen form is the MkDocs slug and only resolves on the docs site. Ref vergil-project/vergil-claude-plugin#833

- **harden path resolution in the audit write guard (#955)**
Resolve the target path with os.path.realpath for a new file as well as an existing one, matching block-worktree-bypass-write, and add a test row. Ref #935.

- **remove the retired standards-and-conventions check (#961)**
The standards-and-conventions repo is retired, so the bootstrap agent's step 3 warned on every machine without the sibling directory. Drop the step, its Standards line in the report format and the matching docs item, and renumber the Hook Guard step. Ref #949


## Documentation

- **drop the manual force-push for a re-report after unfreeze (#941)**
vrg-pr-workflow report-ready now pushes a rebased branch with --force-with-lease on the recorded head after an unfreeze (vergil-tooling#3783), so the unfreeze, rebase, re-report path needs no manual force-push. The first-report diverged case keeps it. Ref #786

- **state the append-only plan-evolution rule (#944)**
Once an epic's first task ships, plan changes are appended as dated what/why entries to an Evolution during execution section in plan.md instead of rewriting the task list; the sub-issues stay the live task list. Ref #832

- **retire starting-work-on-an-issue.md in favour of issue-implement (#947)**
The page told agents to create worktrees with raw git, which the hook guard blocks, and it predates /vergil:issue-implement, which now owns the start-work procedure. Its remaining content was stale or superseded: the worktree layout, rules and agent prompt contract live in the vergil-tooling worktree convention, its CLAUDE.md agent-prompt-contract anchor no longer exists, and its sub-issue flow had the agent create issues without the human approval the doctrine now requires. README's Set up a worktree section now points at issue-implement and the worktree convention; the audit-time links in skills-architecture.md are marked as retired. Ref #834.

- **name the human spec review in the short pipeline chains (#948)**
* docs(epic-create): name the human spec review in the short pipeline chains

The short epic-create chains skipped the human review of the spec that sits between the spec pushback rounds and writing the plan (epic-create Workflow step 5; review doctrine 2.1). Add it to the skill description, the README skill table and the three chains in the docs-site skills index. Ref #842

* docs(skills): rewrap the epic-create entry in the skills index to the line limit

- **retire docs/standards-and-conventions.md (#950)**
The page presented the retired wphillipmoore/standards-and-conventions framework as this repo's canonical standards. Active standards live in vergil-tooling docs/, and the page's AGENTS.md overlay section conflicts with the Claude config ownership model. Deleted outright, matching vergil-actions and vergil-containers. No inbound links outside the changelog and release notes. Ref vergil-project/vergil-claude-plugin#847

- **name the vergil-tooling CLIs vrg-* instead of st-* (#951)**
* fix(hooks): drop the retired st-markdown-standards from the container tool list

vergil-tooling ships no markdown-standards CLI under any prefix today; markdown is linted by markdownlint, already listed. Add list-coverage tests that assert every HOST_TOOLS entry is denied when wrapped, every CONTAINER_TOOLS entry warns when bare, and no entry carries the retired pre-vrg prefix. Ref #936.

* docs(site): name the vergil-tooling CLIs vrg-* instead of st-*

Update the Two-Repo Model table, and reword the enforce-host-container-split description to match what the hook checks: its host-only list (a set of vrg-* CLIs, gh, git, git-cliff) and the language toolchain. Ref #936.

* fix(hooks): restore the host-container-tools.sh file mode

The in-place edit in the previous commit dropped the executable bit the file carried on develop; restore 100755 so the branch changes content only. Ref #936.

- **record decisions for agentic-a11y, vibe, makefile and paad-help (#952)**
Add the four paad 2.0.2 skills child F did not cover to the Other paad skills table: agentic-a11y used by hand, vibe and makefile deviations, paad-help adopted. Add the paad:vibe row to the deviations register; makefile stays a section 7 note. Stop skills-architecture.md citing vibe as covering the develop loop. Ref #844

- **split a task too big for one PR into lettered sub-tasks (#953)**
State the task sizing rule once in epic-create and point to it from the plan stage, the plan pushback rounds, the doctrine's writing-plans step and issue-implement, where a mid-task split is proposed to the human rather than filed. Ref vergil-project/vergil-claude-plugin#934

- **ask the human to undo a completed rebase instead of switch -C (#956)**
Remove the reflog and switch -C instructions, which routed around vrg-git's denial of reset. A completed rebase is now undone only by the human. Ref #945.

- **compare vrg-whoami --mode in the shell in skill preflights (#959)**
Each role preflight now runs a shell comparison that prints ok or not user, so the harness capitalizing the first character of a tool result cannot turn a correct lowercase user into a false stop. Ref #938

- **check the epic body against the spec and plan whenever they change (#960)**
Add an Epic body sync rule and run it after the spec is written, after each review round that changes the spec or plan, after the human spec review, after the plan is written, and before the docs PR. Ref #939.

- **ask the human to restore a moved branch after a failed round check (#962)**
Applies the #825 ruling to the failed-check revert steps: keep the file-level reverts, and when the branch or HEAD SHA moved, stop and give the human the recorded SHA instead of running switch -C or switch --detach. Steps 2 and 3 now read correctly when the revert waits on the human. Ref #954.

- **leave deleting the private directory to issue-implement (#963)**
The skill no longer deletes its private directory after report-ready, a point it never sees. Its caller, issue-implement, deletes it once report-ready has succeeded; until then it must survive so a failed report-ready can resume and security details stay until recorded. Ref vergil-project/vergil-claude-plugin#957.
