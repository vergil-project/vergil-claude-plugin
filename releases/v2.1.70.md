
# Release 2.1.70 (2026-11-14)

## CI

- **move the nightly ops cron to the 01:xx UTC hour (#1068)**
GitHub's schedule events fire 7 to 9 hours late, landing the 06:30 UTC run in the US Eastern working morning. Move it five hours earlier, keeping the per-repo stagger minute. Ref #1066


## Documentation

- **state exactly what a check's fix_status covers (#1072)**
A check's fix_status holds one entry per ID given as a --fix-id (the request's earlier_finding_ids), not every earlier ID, per the merge-review protocol spec and vrg-merge-review-check.


## Features

- **capture the reviewer's reply byte for byte and publish it in the step comment (#1070)**
* feat(merge-review): store the reviewer's reply through a SubagentStop capture hook

The merge-review skill no longer copies the reviewer's reply out of the subagent's output. A new SubagentStop hook, capture-merge-review-result, writes the vergil:merge-reviewer agent's last message byte for byte as result-<step>.md next to its request, with a capture-<step>.json record holding the request_id and the result's SHA-256. A new PreToolUse guard, guard-merge-review-results, denies Write, Edit and NotebookEdit on both files. The skill clears the step's result before each dispatch and confirms the capture after it. Ref vergil-project/vergil-claude-plugin#1065.

* fix(merge-review): clear the shellcheck findings in the capture hook and its tests

* fix(merge-review): make the capture hook and the result guard executable

hooks.json runs both new hook scripts directly by path, so they must be mode 100755 like the other scripts in hooks/scripts/. Ref vergil-project/vergil-claude-plugin#1065.

* feat(merge-review): publish the reviewer's full reply in the step comment

Per the scope change on the issue, the full reviewer reply must survive handoff, not only be stored unchanged. The capture hook now also writes reply-<step>.md, a publishable copy of the same bytes in a fenced block inside a collapsed details section that gives its SHA-256. The skill appends that copy unread to the step comment, so the reply survives the private directory's deletion at report-ready. A result with a security finding is never published: its comment says the reply is withheld and gives only its SHA-256. The result guard also protects the copy, and a reply over 60,000 bytes counts as malformed. Ref vergil-project/vergil-claude-plugin#1065.

* fix(merge-review): restore the result guard's executable mode

An in-place edit dropped the mode back to 100644; hooks.json runs the guard directly by path. Ref vergil-project/vergil-claude-plugin#1065.

* fix(merge-review): clear the shellcheck finding in the reply-copy test

Ref vergil-project/vergil-claude-plugin#1065.

* fix(merge-review): withhold a check reply when an earlier step raised a security finding

A check's fix_status lists every earlier finding, security ones included, and its prose may explain why one still stands, so its reply is not published whenever an earlier step of the run raised a security finding. Ref vergil-project/vergil-claude-plugin#1065.

- **fail when a hook script is not executable (#1071)**
* feat(validate-custom): fail when a hook script named in hooks.json is not executable

check_hook_modes reads every hook command in hooks/hooks.json and requires its script to be tracked in git with mode 100755, naming each offending path. Tests in hooks/tests/hook-modes.test.sh cover executable, non-executable, untracked and missing scripts. Ref #1067.

* fix(validate-custom): mark the literal plugin-root prefix for shellcheck
