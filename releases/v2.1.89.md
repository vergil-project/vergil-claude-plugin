# Release 2.1.89 (2026-11-24)

## Documentation

- **require an ops run after the release when the change touches ops workflows (#1302)**
  Six validations of epic vergil-project/.github#1494 passed check 2 on ops.yml runs that started before the release, so the new report-* jobs never ran. Record a learned validation condition and write it into check 2 of the validation template.
- **name the release runs to check instead of the runs the tag started (#1303)**
  No workflow runs on a fixture's tag push. Step 3 of the release task now names the release PR's CI, the CD run on the main push and the back-merge and dependency-update PRs' runs, keeping the blocked-not-FAILURE rule.
- **say when a human-run step may be recorded without pasted output (#1304)**
  The human's own report of a human-run step is enough when the agent's own checks confirm the step's result independently, and the result comment names those checks; pasted output stays required otherwise. This replaces the bare-claim rule, with epic vergil-project/.github#1494's six fixture release tasks as the example, and epic-implement's gate relay guidance now agrees.
