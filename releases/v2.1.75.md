# Release 2.1.75 (2026-11-17)

## Documentation

- **say that a one-off clears an item's epic size (#1114)**
  A one-off route removes the item's epic-size labels and posts a Size cleared marker, after which earlier sizing comments no longer count (vergil-tooling#4489). Document it in the one-off route, the Epic size section and the skills index.
- **close a task only after its result comment has posted (#1115)**
- **add the managed-files-in-sync learned condition (#1116)**
- **seed a CD-build validation when an epic needs fresh dev images (#1126)**
- **tell the review delegate to fetch nothing in its reality check (#1118)**
  The mode 1 reviewer prompt said the named repos were already fetched but did not forbid a fetch. A delegate fetched an unnamed clone and reported it after the Files written line, which broke the result's last-line check. The template now forbids fetching, pulling or updating any repository, and the rules list says why.
- **require one fresh invocation per acceptance check (#1124)**
  A live validation once loaded the skill under test once and applied its rules to each check, while its result said the commands were run. issue-validate now asks for a fresh invocation per acceptance check and, where that is impossible, for the result to say how each check was exercised.
- **say how to check that a release tag contains a merge (#1128)**
  gh api is denied to the user identity, so three deploy runs each rediscovered the same git method. issue-deploy now gives it: ls-remote for the tag's SHA, then merge-base --is-ancestor in the repo's main clone, which works only once that clone has fetched the tag.
- **forbid a code fence around the reviewer's reply (#1130)**
  The reply example sat inside a four-backtick fence, which reviewers copied, so their replies failed vrg-merge-review-check and cost a re-dispatch. The agent now has an explicit rule that the reply has no surrounding fence, and the example is labelled as wrapped for display only.
