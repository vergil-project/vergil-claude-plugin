# Release 2.1.101 (2026-11-28)

## Bug fixes

- **refuse a task run worded outside the task-run forms (#1468)**
  A task run dispatched with a description outside the four task-run forms (Implement <repo>#N, Fixture change <repo>#N, with or without a retry suffix) escaped guard-task-dispatch and the agent row labels. guard-task-dispatch now also refuses a description that names an issue (#<digits>) and matches none of the forms: as vergil:task-runner it is refused as a malformed task run, and as any agent other than vergil:implementer or vergil:merge-reviewer (absent included) it is refused as a helper naming an issue. epic-implement and fixture-run now state that a fixture run's change, release and validation tasks take the same forms. Tests, the hooks docs entry, the agent row labels note and the README hook summary are updated to match.
- **narrow the task-dispatch guard's issue-reference rule (#1472)**
- **refuse any off-form vergil:task-runner dispatch description (#1473)**

## Features

- **refuse a per-invocation model on a first-try implementer dispatch (#1467)**
  guard-task-dispatch now denies a vergil:implementer dispatch whose model is anything other than absent (or empty or null) or exactly "sonnet", non-string models included. A per-invocation model outranks the Haiku pin, so a first try must pass none; the one escalation retry passes model: "sonnet". Tests, the hooks docs entry, the models map, the README hook summary and the issue-implement writer dispatch and escalation text are updated to match.
